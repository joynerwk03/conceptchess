15Compiled core (C engine) — the big strength jump
Ported board+movegen+search+eval to C (clang->dylib, ctypes). Perft matches python-chess exactly (43x faster movegen). C eval == Python eval to 0.000000 on 6204 positions (interpretability guarantee: fast search optimizes exactly what the explanation shows). C search reaches depth 9 vs Python's 4 at 1s. Head-to-head: +24=6-0 (90%, +382 Elo) vs the ~2018 Python engine. Ladder-anchored at 2442 (2305-2582). Python explanation layer unchanged and still exact.		ACCEPTED—
14Session 7: endgame technique (mating drive)
Diagnostic: KBB/KBN vs K were unconvertable (50-move draws), a won KPvK was lost. Added a 'mating drive' concept (drive enemy king to corner + bring own king up) active only in bare-king endgames -> KBB mate in 67 plies, KBN in 79. Provably neutral outside bare-king endgames (0 on all non-lone-king positions), so no gate needed. Negative results: KPvK bitbase dropped (correctness rabbit hole, tiny Elo); book expansion 250->478 gate-rejected at 36% (-98 Elo) because added sharp lines don't suit the simple eval. Engine stays ~2018 Elo but converts basic mates it was drawing.		ACCEPTED—
13Session 6: opening book (+ SPRT tooling, pruning dead-ends)
Pruning (reverse futility, late-move pruning) all passed the deterministic time-to-depth metric but lost their match gates (42%/29%/40% vs session-5) — the metric rewards node-cutting regardless of strength, and static-eval pruning hurts an engine with a deliberately simple eval. Reverted. The win: a 250-position curated opening book (interpretable, 'Book move: Ruy Lopez'), which gated at +20=2-8 (70%, +147 Elo). New ladder anchor 2018 (1905-2134). Added SPRT early-stopping to the match harness.		ACCEPTED—
